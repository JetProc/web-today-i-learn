# Today I Learn 페이지 만들기

## 프로젝트 소개
HTML, CSS, JavaScript를 활용해 만든 정적 개인 소개 페이지입니다.  
프로필, 자기소개, 기본 정보 표, 9장 갤러리, 인생 작품, TIL 입력 폼과 목록을 포함합니다.

## 배포 링크

## 구현 포인트
- 정적 콘텐츠는 [`js/content-data.js`](./js/content-data.js)에서 한 번에 관리하도록 분리했습니다.
- 페이지 렌더링과 TIL 등록 기능은 [`js/index.js`](./js/index.js)에서 담당합니다.
- 사용자가 추가한 TIL 데이터는 `localStorage`에 저장해 새로고침 후에도 유지됩니다.

## HTML
### 1. 나만의 갤러리에서 사진 9장은 HTML 태그 중 어떤 요소로 표현하는 것이 좋을까? 이유는 뭐라고 생각했는가?
갤러리의 핵심 콘텐츠는 이미지이므로 기본적으로 `<img>` 태그를 사용하는 것이 가장 적절하다고 생각했다.  
이번에는 각 이미지를 하나의 의미 있는 묶음으로 다루기 위해 `<figure>` 안에 `<img>`와 캡션을 함께 넣었고, 이렇게 하면 사진과 설명의 관계를 더 분명하게 표현할 수 있다.

### 2. 뼈대 코드를 기반으로 이미지를 로드하는 방식은 크게 2가지로 나뉘는데 무엇이고 어떻게 사용하고 있는가?
이미지를 불러오는 방식은 크게 HTML의 `<img src="...">`를 사용하는 방법과 CSS의 `background-image`를 사용하는 방법으로 나눌 수 있다.  
이번 페이지에서는 프로필 사진, 갤러리, 작품 썸네일처럼 의미를 가진 이미지가 많아서 `alt`를 함께 쓸 수 있는 `<img>` 방식을 중심으로 사용했다.

### 3. 시맨틱 태그로 문서를 구분할 때, 어떤 기준으로 섹션을 나누고 태그를 적용하는 것이 좋을까?
화면의 모양보다 콘텐츠의 역할을 기준으로 나누는 것이 좋다.  
예를 들어 소개의 시작 부분은 `<header>`, 이동 메뉴는 `<nav>`, 실제 본문은 `<main>`, 서로 다른 주제 묶음은 `<section>`, 독립적으로 읽히는 작품과 TIL 항목은 `<article>`, 마지막 정리 영역은 `<footer>`로 나누면 구조가 명확해진다.

### 4. `<img>` 태그의 `alt` 속성은 왜 필요하며, 어떻게 작성하는 것이 좋을까?
`alt`는 이미지가 보이지 않거나 스크린 리더를 사용하는 상황에서 이미지를 대신 설명해 주는 텍스트라서 접근성을 위해 꼭 필요하다.  
작성할 때는 "이미지"처럼 막연하게 쓰기보다, 그 사진이 전달하는 핵심 정보를 짧고 구체적으로 적는 것이 좋다.

### 5. 이미지를 로드할 때, 상대 경로와 절대 경로를 혼용하면 어떤 문제가 발생할 수 있을까?
로컬에서는 보이던 이미지가 배포 후 깨지거나, 저장소 위치가 바뀌었을 때 일부 경로만 동작하지 않는 문제가 생길 수 있다.  
특히 GitHub Pages 같은 정적 배포에서는 기준 경로가 달라질 수 있으므로, 같은 프로젝트 안의 리소스는 상대 경로로 일관되게 관리하는 편이 안전하다.

### 6. `<meta>` 태그의 viewport 설정과 Open Graph 태그는 각각 어떤 역할을 하는가?
`viewport` 설정은 모바일 브라우저가 화면 너비를 기준으로 페이지를 올바르게 축소하거나 확대하도록 도와준다.  
Open Graph 태그는 링크를 공유했을 때 제목, 설명, 썸네일 같은 미리보기를 어떻게 보여줄지 정하는 역할을 한다.

## CSS
### 1. 나만의 갤러리에서 9장의 이미지를 보기 좋게 배치하려면, Flexbox와 CSS Grid 중 어떤 것이 더 적합할까? 그 이유는?
9장처럼 행과 열이 반복되는 2차원 배치는 CSS Grid가 더 적합하다.  
열 개수, 간격, 반응형 전환을 한 번에 제어하기 쉬워서 규칙적인 갤러리 구조를 만들 때 훨씬 직관적이다.

### 2. 태그 선택자, 클래스 선택자, ID 선택자는 각각 언제 사용하는 것이 적절할까?
태그 선택자는 `body`, `section`, `footer`처럼 공통적인 기본 스타일을 줄 때 적절하다.  
클래스 선택자는 여러 곳에서 재사용되는 카드, 버튼, 갤러리 같은 묶음 스타일에 적합하고, ID 선택자는 `#til`, `#til-form`처럼 문서 안에서 하나만 존재하는 특정 영역을 정확히 집어야 할 때 사용하는 것이 좋다.

### 3. CSS를 HTML 내에 직접 작성하는 것과 별도 파일로 분리하는 것의 차이는 무엇일까?
HTML 안에 직접 작성하면 빠르게 확인하기는 쉽지만, 구조와 스타일이 섞여서 파일이 금방 복잡해진다.  
별도 파일로 분리하면 역할이 나뉘어 읽기 쉽고, 여러 페이지에서 재사용하거나 유지보수하기도 훨씬 편하다.

## JavaScript
### 1. `document.getElementById()`와 `document.querySelector()`의 차이는 무엇인가?
`getElementById()`는 ID 하나만 빠르게 찾을 때 사용하는 메서드다.  
반면 `querySelector()`는 ID뿐 아니라 클래스, 태그, 속성 선택자 등 CSS 선택자 문법을 그대로 사용할 수 있어서 더 유연하다.

### 2. 이벤트 리스너를 사용해서 자기소개 페이지에서 활용할 수 있는 이벤트에는 어떤 것들이 있을까?
예를 들어 TIL 폼 등록에는 `submit`, 초기화 버튼에는 `reset`, 갤러리 이미지 확대에는 `click`, 입력 중 글자 수 표시에는 `input`, 메뉴 강조나 애니메이션에는 `scroll` 이벤트를 활용할 수 있다.  
이번 구현에서는 TIL 등록 기능을 위해 `submit`과 `reset` 이벤트를 사용했다.

### 3. `innerHTML`로 DOM을 조작할 때 주의해야 할 점은 무엇일까?
문자열을 그대로 HTML로 해석하기 때문에, 사용자 입력이 섞이면 의도하지 않은 태그가 삽입되거나 보안 문제가 생길 수 있다.  
또 기존 노드를 통째로 다시 그리게 되어 이벤트가 끊길 수도 있어서, 가능한 경우에는 `createElement()`와 `textContent`를 사용하는 편이 더 안전하다.

## 배포
### 1. GitHub Pages로 배포한 페이지에서 TIL을 작성하면, 새로고침하거나 재배포했을 때 데이터가 유지될까? 그 이유는?
JavaScript 변수에만 저장한 데이터라면 새로고침할 때 메모리가 초기화되므로 유지되지 않는다.  
하지만 이번 구현처럼 `localStorage`에 저장하면 같은 브라우저에서는 새로고침 후에도 유지되고, 대신 브라우저를 바꾸거나 저장소를 다른 사람과 공유해도 그 데이터가 같이 전달되지는 않는다.

### 2. JavaScript로 추가한 데이터를 영구적으로 저장하려면 어떤 방법이 있을까?
가장 간단한 방법은 브라우저의 `localStorage`나 `IndexedDB`를 사용하는 것이다.  
여러 기기에서 같은 데이터를 유지하려면 결국 서버나 데이터베이스가 필요하고, Firebase나 Supabase 같은 백엔드 서비스를 붙이는 방식도 사용할 수 있다.

## 이번 과제에서 새롭게 배운 점
- 시맨틱 태그를 역할 기준으로 나누면 화면 구조와 코드 구조를 함께 정리할 수 있다.
- 반복되는 이미지 배치는 Flexbox보다 Grid가 더 자연스러운 경우가 많다.
- 정적 페이지에서도 `localStorage`를 활용하면 사용자 입력을 간단히 유지할 수 있다.
- 콘텐츠를 HTML에 직접 쓰지 않고 별도 JS 데이터 파일로 분리하면 교체와 관리가 훨씬 쉬워진다.
